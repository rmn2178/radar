# RADAR Centre — Website & CMS

Official digital presence for **RADAR Centre, Rajalakshmi Institute of Technology (RIT), Chennai**: an interdisciplinary research centre working across medical imaging, radiomics, AI-driven healthcare, RF/microwave imaging, biomedical sensing and intelligent healthcare systems.

This repository contains a Next.js App Router application with a public institutional website and a Supabase-backed administrative CMS at `/admin`. Public content and admin editing share the same database; publishing content does not require a code deployment.

## Stack

- Next.js App Router, React, TypeScript, Tailwind CSS v4
- Motion (Framer Motion), Lucide icons, Manrope + DM Serif Display
- React Hook Form + Zod validation
- Supabase PostgreSQL, Auth, Storage and Row Level Security
- Vercel + GitHub deployment (free-tier compatible, no paid AI API)

## Quick start

```bash
npm install
cp .env.example .env.local   # then fill values, or leave blank for local preview
npm run dev
```

Open http://localhost:3000.

### Local preview without Supabase

When no Supabase variables are set and `NODE_ENV` is not `production`, the site renders the verified seed content from `src/data/seed.ts` and shows a labelled preview banner. In this mode:

- Public pages render from the seed fixture (read-only).
- `/admin` sign-in and all write/upload/contact APIs return `503` — they never fake success.
- To force preview in a production build, set `RADAR_CONTENT_PREVIEW=true` explicitly. Do not use this for a real public deployment.

### Connect Supabase

1. Create a Supabase project.
2. Run the SQL migrations in `supabase/migrations/` in order (SQL editor or `supabase db push`).
3. Run `supabase/seed/initial-radar-content.sql` (generated by `npm run seed:generate`). It is idempotent.
4. Create the administrator Auth user and assign the `admin` role — see [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).
5. Create the public `radar-media` storage bucket (the migration also attempts to create it and apply policies).
6. Fill `.env.local`:

```
NEXT_PUBLIC_SUPABASE_URL=https://<project>.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<anon/public key>
NEXT_PUBLIC_SITE_URL=http://localhost:3000
RADAR_ADMIN_LOGIN_EMAIL=<admin auth email>
RADAR_RATE_LIMIT_SECRET=<random 32+ char secret>
```

Only the anon/publishable key is used by the application. **Never** add a service-role key to any `NEXT_PUBLIC_` variable or to the deployed runtime.

## Project layout

```
src/app/(public)/      Public website (home, about, research, members, events, projects, contact, detail routes)
src/app/admin/         Passcode login + protected CMS
src/app/api/           Auth, contact, and admin content/media/enquiry APIs
src/components/cms/    Typed section registry + page renderer (no executable CMS code)
src/components/public/ Institutional UI components
src/components/admin/  Dashboard, editors, media library, page builder
src/lib/               Supabase clients, auth guards, validation, data access
src/data/seed.ts       Verified initial content (single source for seed SQL)
supabase/              SQL migrations + generated seed
docs/                  Architecture, database, admin, deployment, security, content guides
```

## Content integrity

Initial content is transcribed from the two supplied website briefs. The referenced `RADAR (July-Aug)Report.pdf` was **not present** in the workspace, so no additional facts were inferred. Undated activities remain undated, the contact email is blank, the AI medical-scan project is a draft pending details, and “paper uploaded” is never labelled as accepted/published. Original logos are preserved byte-for-byte in `public/brand/`.

## Verification status

Automated checks are green locally: `npm run check` (lint, typecheck, 22 unit tests, production build) and `npm run test:e2e` (9 Playwright checks against a labelled read-only preview).

The full stack was additionally verified against a **live Supabase project** on 2026-11-10: migrations and seed applied via `supabase db push`; a real admin Auth user provisioned with an `admin_profiles` role; and an opt-in end-to-end run that confirmed public pages read only published content, admin sign-in / CRUD / logout, draft write → hidden → publish → visible → delete, contact submission with admin-only reads, and media upload / alt-caption edit / delete with storage cleanup. An anonymous REST probe confirmed drafts, `admin_profiles`, enquiries, revisions and logs are not readable, and anonymous Storage writes are rejected.

Vercel hosting has **not** been connected yet — add the environment variables from [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md) and deploy there when ready.
